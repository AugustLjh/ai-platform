# AI 功能排产计划

更新时间：2026-03-09

## 目标

在不启动“智能体工作台”的前提下，按业务价值和实现成本推进当前项目的 AI 能力，优先把知识问答做成可追溯、可调优、可运营的企业能力。

## 排期总览

### P0 可追溯知识问答

目标：让知识库问答从“能答”升级到“答案可验证、未命中不乱答”。

范围：
- 聊天回答增加引用来源、命中片段、文档分数、知识库信息。
- 未命中时返回明确提示，不直接让模型自由发挥。
- 前端聊天页展示引用卡片和检索状态。
- 会话历史保留引用元数据。

当前执行状态：已完成

### P1 知识库自动加工

目标：让上传的文档自动生成可消费知识。

范围：
- 自动摘要、关键词、标签、FAQ。
- 文档类型识别。
- 相似文档检测和重复上传提示。
- 在知识库详情页展示 AI 加工结果。

当前执行状态：进行中

### P2 检索评测中心

目标：把召回测试升级成可保存、可对比、可复盘的评测体系。

范围：
- 测试集管理。
- 多配置对比。
- 命中率、首条命中率、人工反馈评分。
- 一键将评测配置设为生产配置。

当前执行状态：进行中

### P3 AI 运营与治理

目标：补齐模型路由、质量反馈、预算和审计能力。

范围：
- 按场景路由模型。
- 主备模型回退。
- 按租户/知识库/功能统计成本。
- 问答质量反馈与低质量样本沉淀。
- 审计链路和配置版本追踪。

当前执行状态：进行中

## 执行顺序

1. P0 可追溯知识问答
2. P1 知识库自动加工
3. P2 检索评测中心
4. P3 AI 运营与治理

## 执行约束

- 不在 shell 中对后端项目执行编译或运行操作。
- 原因：当前环境资源不足，且后端运行环境不健全，相关验证以静态检查、代码审阅和前端可独立执行的构建为主。
- 项目使用 Docker 时，不直接创建、重构或重建镜像。
- 如确需重构镜像，由我明确说明原因、时机和建议命令，再由你手动执行。

## P0 任务拆分

### 后端

- Runtime 在 RAG 检索后返回引用文档与命中片段元数据。
- Runtime 在知识库未命中时返回标准化提示与检索状态。
- Go 平台层透传并持久化聊天消息 metadata。

### 前端

- SSE 解析保留 metadata，不只消费 `content`。
- 聊天消息支持渲染引用卡片。
- 聊天消息支持渲染“未命中知识库”提示。
- 历史消息恢复引用展示。

### 验收标准

- 选择知识库后，回答可看到引用来源与片段。
- 未命中时有明确提示。
- 刷新页面后，历史会话仍能看到引用信息。
